# ADR-0007: 官方文件只写能力与价值，不写对号入座的应试表述

日期: 2026-10-11 · 状态: Accepted

## 决策

所有随包分发的文件（SKILL/README/references/commit message）描述功能时
只写「能力是什么、解决什么问题」；**不写**「针对某评测的某失分项优化」
一类对号入座的表述。

## 背景

评测是质量的体温计，不是产品的目标函数。把评测条目写进官方文件，等于
宣告"为分数优化"，既不尊重真实用户（他们关心的是引用核验本身），也让
每一次能力迭代看起来像应试。自有基准（留出集）上的诚实数字与校准披露
不受此限——透明是能力，应试是姿态。

## 后果

- 能力迭代照常做，落笔只答"这解决了什么问题"
- 文档质量的改进由结构（入口/路由/反模式）承载，而非应试话术
