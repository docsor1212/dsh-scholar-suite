# 最佳实践指南（Best practices）

> 场景级怎么用：什么时候用什么命令、什么信号该信什么、常见误用怎么避。
> 全部建议基于随包能力边界矩阵与实测口径；v6.1.0 新增。

## 1. 检测前：选对口径

| 你的场景 | 建议 |
|---|---|
| 普通中文学术自查 | `pp.py detect 文稿` 默认口径即可 |
| 医学/生命科学论文 | 装监督模型（`pp_setup.py --guide`）；不装则**只采信 @high 判定**——降级档对医学语域系统性高估（@medium 人类误报约 59%） |
| 投稿前预检 | `ai_detector.py 文稿 --profile journal`（分学科语境 + 20-25% 参考线，附不可互换声明） |
| 英文文稿 | 按设计走纯规则骨架，结论仅参考；不要把英文分数与中文混比 |

## 2. 段落归因的正确用法（最容易被误用的功能）

- 段落级 hi/med/lo 是**人工复核排序辅助**，不是自动判定（校准最优工作点精度 0.60、覆盖 63%，低于自动判定线）。
- 正确姿势：跑 `pp.py paragraph` → 从 hi 段自上而下人工看 → 只改你确认生硬的句子。
- 错误姿势：把 hi 段全删重写、或拿单段分数当「这段是 AI 写的」证据。人机混写文档尤其如此（文档级 AUROC 0.52-0.54）。

## 3. 改写循环（检测→改→验证）

```
第 1 轮  pp.py workflow 稿件      # 全量报告 + 行动清单（v6.1.0 起自带 explain 人话版）
        pp.py fix 稿件 --top 10   # 句子级指位+策略（不代改，决定权在你）
人工改写（以内容质量为准——分数下降不等于写得更好）
第 2 轮  pp.py rewrite-check 原稿 改稿   # 同引擎对比：降了多少、哪些特征清除
多轮后   pp.py trend 报告目录/           # 跨轮轨迹：整体在降还是反弹
```

## 4. 批量组织

- 目录只放要检测的 .txt/.md/.docx（<5MB/个；超大会跳过）。
- 默认熔断（连续 5 个失败即中止）保护你不对着整目录坏文件白烧时间；`--circuit 0` 关闭。
- 结果汇总：`--csv` 出行级 CSV → `pp.py batch-report scores.csv` 出 HTML 汇总。

## 5. 模式与可信度

- 引擎会如实披露档位：每份报告带 `degraded_mode`/`degraded_notice`。
- 分数不与知网/万方等任何机构检测器互换（口径不同，非谦虚是事实）；自检定位见各报告 integrity_notice。
- 模型文件不要替换/重量化（实测概率漂移）；只接受作者签发指纹。

## 6. 合规

- 供作者自查与质量改进；不用于规避机构 AIGC 检测。
- 需要 AI 使用披露时用 `pp.py aigc 文件`（元数据/C2PA/显式声明自查，对应中国 2025-09 标识办法）。
