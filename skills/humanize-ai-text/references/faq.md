# 常见问题 FAQ（含迁移指引）

> 覆盖评测与用户反馈中的高频问题。没找到答案时，先跑 `python scripts/pipeline.py 你的文件 -o out.txt` 看报告，再按报告里的指南深改。

## 基础

**Q0：第一次用，最容易踩的坑？**
读 `references/pitfalls.md`——27 条集中式常见错误清单（参数误用/编码事故/守卫
误读/流程合规），每条带正确做法。TL;DR：跑 pipeline → 读报告 → 按指南深改 →
verify → compare。

**Q1：这个工具和 paper-polisher-pro 什么区别？**
paper-polisher-pro 是综合润色工具箱（术语、翻译腔、比喻审计、AIGC 标识合规、期刊预检），本工具专攻「风格自然化」一件事：风格特征自查 → 机械清理 → 深改简报 → 完整性守卫。两者可同时使用互不冲突——先本工具去模板腔，再 paper-polisher-pro 做全稿润色。

**Q2：报告里的分数是检测器分数吗？**
不是。分数是对写作模式（套话密度、句长均匀度、模板结构）的本地启发式统计，不代表任何外部服务的测量结果，更不说明文字由谁写。怎么理解这个分数：它度量的是「模式密度」——比如 50 分意味着每千字命中约 X 处可改写特征；同一篇稿子改掉八股开场后分数会实质性下降，所以它适合当**改稿进度条**用。它不能当「检测器」用：对流畅的现代模型文本几乎不触发（诚实边界节有实测数字），也别反过来拿低分证明「是人写的」。详见 SKILL.md「诚实边界」与 `references/pdf_confidence.md` 末节的口径提醒。

**Q3：支持什么文件格式？**
纯文本（.txt）、Markdown（.md）、**Word（.docx）**、以及 **PDF（v1.6.0 起实验性
直读，限英文文本型；加密/扫描件拒收，CJK/嵌入字体尽力识别并拒收、可能漏网——
抽取结果请人工检查）**。stdin 也支持：
`echo "文本" | python scripts/detect.py`。
Word 文件直接传 .docx 即可（支持直读）——不要自己另存成 .doc/.rtf（这两类
不是本工具能解析的格式，会得到「疑似二进制」报错）。

**Q4：会改坏我的数据吗？**
机械清理层设计上不触碰数字/引用；深改层由 agent 按指南执行，改完必须过 `verify.py`——数字、统计量、DOI、PMID、年份、缩写、术语表任何丢失都会 exit 1。守卫还会对「凭空新增的数字」告警（编造防线）。历史实测：改写中 p 值篡改、两臂互换、整句含电话号码误删，全部被守卫拦截过。

## 使用

**Q5：一定要跑四个脚本吗？**
不用。`python scripts/pipeline.py draft.txt -o out.txt` 一条命令跑完自查→清理→守卫→报告；要确定性删八股加 `--deep`，要 CI 门禁加 `--ci`。分步入口（detect/transform/verify/compare 单独跑）是为这些场景保留的：只清残留不动风格（单跑 transform）、只想看哪几句最该改（单跑 plan --handoff）、把守卫接进自己的脚本（单跑 verify 取退出码）。

**Q6：术语表（--terms）怎么准备？**
先跑 `python scripts/extract_terms.py 原稿 -o terms.txt` 自动生成草稿（大写缩写、
书名号/引号内术语按频次排序），人工删改后使用。每行一个术语，`#` 开头是注释。
医学文本建议补充：药名（含商品名）、基因符号（鼠源首字母大写形态如 Myc 也要列）、
量表名、仪器名。不提供术语表时，守卫仍查数字/DOI/PMID/年份/全大写缩写。
赶时间可 `pipeline.py 原稿 -o out.txt --terms auto`：自动草稿直接进管线（守卫口径
偏松，正式稿件建议人工过一遍后重跑）。

**Q7：退出码怎么看？**
`verify.py` 是严格契约方：`0`=完整性 PASS、`1`=完整性 FAIL（有数字/引用/术语被动过——修改改稿，不是改守卫）、`2`=用法或文件错误。`detect/transform/compare/pipeline` 把判定写在输出报告里，完成即返回 `0`（用法/文件错误 `2`）——按退出码分支的脚本请以 verify.py 为准。CI/agent 想让 detect/pipeline 也输出机器退出码，加 `--exit-verdict`（或短别名 `--ci`）。全表见 `references/errors.md` 第一节。所有脚本支持 `--version`。

**Q8：检测误报了正当术语怎么办？**
两层解决：①词表自带术语保护（mutational landscape、pivotal trial、robust regression、序列对齐、沉淀反应、心室重塑、串联质谱等已豁免）；②仍误报的，用 `learn_guards.py from-text 术语 样本.txt` 固化成用户守卫（升级不丢），或在 `scripts/patterns_*.json` 的 `term_guards` 加一条你的搭配（allow_before/allow_after），并欢迎反馈补充词表。

**Q9：分数多少算"有问题"？**
0-27 低（正常）；28-49 中（有模板腔，可改可不改）；50+ 高（建议按指南深改）；报告会给出具体剩余特征清单。分数是密度统计，短文本（<15 单元）自动降权并标注"仅供参考"。
两个实用读法：①看**结构分布**比看总分有用——报告按类别列出剩余特征，套话 12 处+翻译腔 3 处的 40 分，远比单一「en_vocab 12 处」的 40 分好改；②用 `stylecheck.py 改稿 --compare 原稿` 看分项差值，总分不降但句长 CV 从 0.2 升到 0.45，就是节奏真改好了。

**Q10：数字前后打架有工具查吗？**
有。`python scripts/check_stats.py 原稿`（v3.2.0）查三类内部一致性问题：百分比清单加起来不是 100（只查带「分别/依次/构成比」等划分用语的句子——合并症占比这类合法的非穷举清单不误报）、同一分组前后 n 不一致（「干预组（n=45）」vs「最终干预组（n=48）」会归一化后比对）、p= 与 P= 风格混用。退出码与 check_terms 相同（0 一致 / 1 有问题 / 2 用法错误），可直接接 CI——注意按默认输出取退出码：`--json` 模式恒返回 0，分支看 JSON 的 total 字段。建议在**定稿/送审前**对原稿跑一遍（改稿若动过数字，先过 verify 守卫再说）。它查的是内部一致性，不是统计正确性——结果是否真实以原始数据为准。
分章分稿用 `--batch 目录`（跨文件聚合），或直接 `pipeline.py 原稿 --check-stats`
并入主管线；要交付级汇总用 `pipeline.py 原稿 --bundle 目录`（六件套自查包）。

**Q11：术语前后不统一有工具查吗？**
有，两个口径：单文件 `check_terms.py 文稿` 查同篇内同一概念的多种称谓
（患者/病人、肾功能/肾脏功能，内置 8 域 27 组 55 变体 + 用户自定义对）；跨文件
`check_terms.py --batch 目录`（v3.7.0）额外查**变体漂移**——摘要用「患者」、
讨论用「病人」这种各文件内部一致、合起来不一致的情况，单文件模式看不见。
报告给「建议统一为」（按全局出现频次推荐），exit 1=有问题
（含部分文件读取失败且幸存文件零发现的情形——防假 clean；有读取失败时
先看 [跳过] 明细）。扫描范围 .txt/.md/.docx（不含 .pdf）；`--json` 与单文件
同口径恒返回 0，分支看 total 字段。

## 批量与断点续传

**Q12：批量跑了一半中断（Ctrl+C/断电/超时），要全部重跑吗？**
不用。v3.7.0 起批量模式每处理完一个文件就把结果原子落进目录下
`.pr_batch_state.json`，重跑加 `--resume` 即跳过已完成文件：

```bash
python scripts/detect.py --batch 目录 --resume
python scripts/pipeline.py --batch 目录 --resume
```

规则：文件内容没变（大小+修改时间一致）→ 直接复用上次结果；文件改过或上次
失败的 → 自动重跑。不加 `--resume` 则从头重建进度。续跑请用与首跑相同的
参数（--profile/--lang/--terms 等——进度只存结果不存参数）。detect 与 pipeline 的进度
互不干扰（同目录各认各的记录）。批量还有二遍重试队列：首遍因 IO 抖动/超时
失败的文件会自动重试一次（「（重试成功）」标注）。

**Q13：能一次扫整个目录吗？出什么结果？**
能。`--batch 目录名` 一次处理全部 .txt/.md/.docx/.pdf：detect 出逐文件评分汇总
（stdout/`--json`/`--html` 均可），pipeline 逐文件「清理+守卫」出汇总 CSV。
大规模目录建议 detect 先扫一遍找高分文件，再对重点文件单跑 pipeline。
注意：`pipeline --batch` 的产物是「清理+守卫」的汇总 CSV 台账，清理稿本身
不落盘（`-o` 只命名台账文件）——要留下清理稿，对重点文件单跑
`pipeline.py 原稿 -o 改稿.txt`。

## 输入与报错

**Q13b：Windows 记事本存的 GBK 文件能直接用吗？**
能。v4.0.0 起编码自动识别：UTF-8 / UTF-16（带 BOM）/ GBK·GB2312·GB18030
直接透明转码处理，不再要求先「另存为 UTF-8」；转码会在 stderr 提示
（程序化调用 read_text_ex 时另经 meta.encoding 字段透出），文件本体不被改动。
两类情况仍会拒收并给指引：彻底无法识别的编码；以及**不含任何中文标点的
GBK 文件**（判别保守——这类文件与「损坏的 UTF-8」无法可靠区分，
另存为 UTF-8 后即可处理）。

**Q14：报错信息怎么读？**
所有错误统一两行：第一行「错误:」说清出了什么问题（含常见原因），第二行
「处置建议:」告诉下一步做什么。例如输入了 Word 另存的 .doc 文件，会提示
「疑似二进制或损坏文件」并建议直接用 .docx（GBK/UTF-16 编码已能自动转码，
见 Q13b）。完整错误码与处置速查：`references/errors.md`。

**Q15：PDF 直读的「置信度」是什么？怎么用？**
PDF 抽取的文字质量参差不齐（嵌入字体缺映射会抽出乱码），工具在抽取后自评
三档置信度：**高**=放心用；**中**=可用但建议抽查关键句（数字/引用）；
**低**=乱码典型形态。**v3.8.0 起缺省安全门=中**（detect/pipeline/plan 同款）：低置信默认直接拒收并说明
原因，不再混进检测报告与守卫输入；`--pdf-min-confidence 低` 恢复旧的「只标注
不拦」，`高` 收得更紧（中置信也要抽查后人工放行）。
批量模式自带熔断：同批 ≥3 个 PDF 被拒会输出批级警告——通常说明是来源质量
问题（同一批扫描件/同一导出器），逐文件硬调门闸不如先查源头。
拒收了怎么办：优先从原编辑器（Word/LaTeX/Overleaf）导出 UTF-8 纯文本，
扫描件先 OCR。校准细节见 `references/pdf_confidence.md`。
中文 PDF 与扫描件明确不在直读范围（拒收并提示），别硬调门闸。

**Q16：多大文本算"太大"？**
v1.4.0 起不再需要手动切分：detect/pipeline 对超 1MB 文本**自动分块**处理（按段落
边界，报告会标注分块口径与块数），内存峰值恒定。注意完整性守卫（verify.py）始终
整文比对——这是红线语义，不可分块。

## 边界

**Q16b：超大规模文件扫描超时会全部作废吗？**
不会全部作废。v3.9.0 起分块扫描自带降级：单块超时先以 2× 预算自动重试，
仍超时就跳过该块继续其余部分，报告明确标注「覆盖不全，勿当完整报告使用」
（JSON 的 degraded_chunks 字段给具体区间）；CI 门禁（--exit-verdict）把
降级视为不完整扫描直接拦停（exit 2；plan 与 pipeline --batch 仍为整体失败
口径）。全部分块都超时会响亮报错——那说明文件本身病态，请按章节拆分。
verify 判 FAIL 时每条违规附「怎么修」处方（数字丢失类附原句锚点），
不再需要人工猜改哪里。

**Q17：能保证某种评审结果吗？**
不能，也不承诺。本工具改善写作质量与自然度；任何承诺「保证不被判为机器生成」的服务都不可信。合规义务（AI 使用披露）在作者本人，见 references/compliance.md。

**Q18：--structure 的章节降权会不会帮作者"藏住"方法段的机器味？**
不会。降权只归一综合分（方法段的固定句式是领域惯例，公平计量）；各章节原始分
仍在报告中逐项展示，任何人都能看到完整数据。「藏匿」不是本工具的设计，也
不符合它的诚信立场（见 compliance.md 拒绝清单）。

**Q19：报告能导出成网页吗？**
能。`--html report.html` 生成单文件 HTML（无外链可直接存档/转发）；compare 的
HTML 含逐句增删对照，复核改稿最直观。stylecheck 也有 `--html`。

**Q20：transform 的激进模式（-a）什么时候用？**
适合：非正式文本的破折号堆叠、空泛开场白清理。不适合：学术方法段的插入语破折号、
任何将直接提交的文本（改完必须人工复核）。普通模式（不带 -a）已经能清模型残留、
客套句、标点与安全填充语——先跑普通模式看报告再决定要不要 -a。

**Q21：博客/公众号/公文这类非学术文本，评分偏高怎么办？**
用 `--profile general`：学术八股和公文过渡语在人写的非学术文本里是常态，general
模式把这些信号降权 60%（黑话、模型残留、节奏信号不受影响）。默认 `academic`
始终按学术论文口径标定，处理论文时不需要加参数。

**Q22：这个工具会联网吗？会读我的其他文件吗？**
不会、不会。全部脚本仅 Python 标准库、零网络请求；只读取你作为参数传入的文件，
只写入你用 `-o`/`--suggestions`/`--html`/`--track` 等旗标指定的输出路径
（批量断点进度写在批量目录自身的 `.pr_batch_state.json`）；不读环境变量、
不创建子进程和定时任务。详见 SKILL.md「权限与环境声明」。

**Q23：2026 年了，检测技术都在进步，这套"质量优先"路线还成立吗？**
更成立了。公开研究显示：①单纯同义转写并不能让文字变好——质量优先路线的
价值不随工具演进贬值；②节奏与结构层面的建议之所以有效，是因为它们让文字
回归真实写作的质量，本工具不以任何外部产品为目标或参照；③正式学术文体被
自动化评审误判仍是行业痛点——被误判的真实作者依然是第一等用户。质量优先
是写作本身的标准，长期成立。

**Q24：我是从旧版页面过来的，有变化吗？**
功能全集在这里且只增不减：旧版全部能力（双语自查/机械清理/深改手册/完整性
守卫/前后对比）至今都在，且持续新增（统计一致性/术语变体组/批量续传等）。
同代码库双页发布、版本同号；以后更新认准你所在页面自己的名称（本页），
姊妹页永久保留作为入口。
